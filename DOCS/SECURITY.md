# Защита данных в платформе учёта тем ВКР

Документ описывает, **каким образом реализована защита данных** — для отчёта, защиты ВКР и эксплуатации системы.

## 1. Аутентификация и сессии

- Вход через **Appwrite Auth** (email + пароль).
- Сессия пользователя хранится в клиенте Appwrite SDK; для серверных API передаётся через заголовки (`X-Appwrite-Session`, fallback-cookies) — см. [`src/lib/appwriteApiFetch.ts`](../src/lib/appwriteApiFetch.ts) и [`src/lib/serverAppwrite.ts`](../src/lib/serverAppwrite.ts).
- **Middleware** ([`src/middleware.ts`](../src/middleware.ts)) не пускает на защищённые страницы без валидной записи пользователя в cookie `auth-storage`.
- Публичная регистрация **закрыта** после создания первого администратора (`/api/bootstrap/has-admin`).

## 2. Разграничение доступа (RBAC)

| Роль | Доступ |
|------|--------|
| **ADMIN** | Все кафедры, все темы, операторы, статистика, резервная копия |
| **OPERATOR** | Только своя кафедра: темы и справочник кафедры в урезанном виде |

- Маршруты `/admin/*` в middleware доступны только при `role === ADMIN`.
- **Серверные API** повторно проверяют роль и `departmentId` — оператор не может запросить чужую кафедру подстановкой параметра в URL.

## 3. Работа с данными только через сервер

Чувствительные операции (список тем, создание, ИИ-проверка, история, бэкап) выполняются через **Next.js API Routes** с **серверным ключом** `APPWRITE_API_KEY`. Клиентский браузер не обращается к коллекциям напрямую с правами на всю базу.

Секреты **не попадают в браузер**:

- `APPWRITE_API_KEY`
- `OPENAI_API_KEY`

Они задаются только в `.env.local` на сервере (см. [`.env.example`](../.env.example)).

## 4. Контроль повторяемости тем

1. **Нормализация** заголовка и уникальный индекс `(departmentId, normalizedTitle)` в Appwrite.
2. **ИИ-проверка** (OpenAI): семантическое сравнение с темами той же кафедры, выдача **процента схожести** — только на сервере, по кнопке в форме темы.
3. Локальная подсказка о точном дубликате по нормализованной строке в интерфейсе.

## 5. Журнал изменений (аудит)

Коллекция **`topic_audit_log`**: кто (`userId`, `userName`), когда, действие (`create` / `update` / `delete`), diff полей. Запись выполняется при каждой операции с темой на сервере. Просмотр — через `GET /api/topics/[id]/history` с той же проверкой доступа, что и к самой теме.

## 6. Резервное копирование

- **Скрипт:** `npm run db:backup` → JSON в папке `backups/` (в git не коммитится).
- **Админ:** кнопка «Скачать резервную копию БД» на странице статистики → `GET /api/admin/backup` (только ADMIN).

Рекомендуется периодически сохранять копии на отдельный носитель / облако вне Appwrite.

## 7. Рекомендации по эксплуатации

- Развёртывание по **HTTPS**.
- Не коммитить `.env.local` в репозиторий.
- Ограничить права API-ключа Appwrite минимально необходимыми (Databases, Users).
- Регулярно ротировать ключи Appwrite и OpenAI при компрометации.
- В консоли Appwrite настроить политики проекта (домены, лимиты) по документации Appwrite.

## 8. Персональные данные

В темах могут храниться ФИО студента, руководителя, группа, год выпуска. Доступ ограничен ролями и кафедрой; аудит фиксирует изменения. Для соответствия локальным требованиям (152-ФЗ и т.п.) организация-заказчик должна дополнительно утвердить политику обработки ПДн и сроки хранения — платформа предоставляет технические средства учёта и ограничения доступа.
